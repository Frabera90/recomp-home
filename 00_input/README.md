# Input Upload Guide

Use this folder for all raw material.

Do not worry about making it perfect. The important thing is to put each material in the right area so Codex can analyze it without mixing product, app UI, landing and references.

## Current RE-COMP Screens

Path:

`00_input/screenshots/current_recomp/`

Use for:

- old RE-COMP screens
- current app screens
- RE-COMP as-is material
- screens made before the new Health OS direction

Analysis goal:

Understand what exists, what should be preserved, what should change and what creates UX risk.

## App UI References

Path:

`00_input/references/app_ui/`

Use for:

- Superpower app screens
- Bevel app screens
- Whoop app screens
- Apple Health references
- Nike app references
- mobile dashboard references
- health, nutrition, recovery and coaching UI references

Analysis goal:

Extract product UI patterns for the RE-COMP app.

## Landing Page References

Path:

`00_input/references/landing/`

Use for:

- landing page screenshots
- hero references
- pricing sections
- testimonial sections
- product storytelling references
- premium health website references

Analysis goal:

Extract web and marketing patterns. Do not automatically apply these rules to the app UI.

## Component References

Path:

`00_input/references/components/`

Use for:

- single cards
- navigation patterns
- onboarding steps
- charts
- score modules
- comparison sections
- forms
- modals
- pricing components

Analysis goal:

Extract reusable component patterns and decide whether they belong to app, landing or both.

## Mobbin References

Path:

`00_input/references/mobbin/`

Use for:

- screenshots from Mobbin
- UI patterns from comparable apps
- onboarding, dashboard, paywall, profile, health tracking or analytics examples

Naming suggestion:

- `mobbin-onboarding-health-01.png`
- `mobbin-dashboard-card-01.png`
- `mobbin-pricing-section-01.png`
- `mobbin-coach-flow-01.png`

Analysis goal:

Identify patterns worth adapting, not copying directly.

## Brand References

`00_input/references/brand/`

Support brand consistency across app, landing and marketing.

## Claude Exports

Path:

`00_input/claude_exports/`

Use for:

- Claude-generated screens
- exported UI concepts
- AI-generated product ideas from other tools

Analysis goal:

Reconcile these with the RE-COMP system. They are input material, not automatic truth.

## Commands To Use After Uploading

For general updates:

`Analyze new project material and update context.`

For app UI only:

`Analyze new app UI references only. Do not update landing direction.`

For landing only:

`Analyze new landing references only. Keep app UI separate.`

For current RE-COMP screens:

`Analyze current RE-COMP screens and identify what to preserve, remove and redesign.`

For Mobbin/component references:

`Analyze component references and extract reusable patterns for RE-COMP.`

## Rule

Landing and app share positioning, brand and quality bar.

They do not need to share the same UI structure.
