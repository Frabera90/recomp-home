# Knowledge Graph

The `.md` files are not static documentation.

They are a connected product knowledge system.

## Dependency Chain

`02_context/product.md`

defines what RE-COMP is.

`02_context/positioning.md`

defines where RE-COMP sits in the market.

`02_context/goals.md`

defines what the product must achieve.

`09_decisions/`

records why important choices were made.

`01_analysis/system-map.md`

maps the product systems.

`01_analysis/flow-inventory.md`

turns the system into user journeys.

`03_design/design.md`

translates positioning into visual direction.

`03_design/components.md`

turns visual direction into reusable interface rules.

`04_flows/`

stores detailed flow specifications.

`05_marketing/`

translates the product system into public messaging.

## Rule

When editing a downstream file, check upstream files first.

Example:

Before changing components, check:

- product definition
- positioning
- design direction
- relevant decisions

## Purpose

This prevents isolated screens, random style shifts and undocumented product drift.
