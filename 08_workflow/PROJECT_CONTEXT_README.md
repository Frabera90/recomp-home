## Domain Rule

After reading the shared context, each chat must continue only inside its own domain.

Examples:

- App reads brand and services, but does not rewrite brand.
- Product Owner reads app, design-system and roadmap context, but does not edit product UI code.
- App and Product Owner use `04_flows/FEATURE_INDEX.md` to identify flows by feature and screen ID.
- Social reads app and services, but does not edit app.
- Presentation reads app, landing, social and images, but does not modify them.
- Branding reads design system and product context, but does not change app UI.
- Design System reads services and brand context, but does not invent product claims.

## UI Decision Skill

For important UI decisions, use the local Codex skill:

- `recomp-ui-director`

Use it before changing:

- app UI
- landing UI
- design-system components
- playground structure
- Liquid Glass
- Soft Metal surfaces
- navigation
- cards
- forms
- charts
- overlays
- motion that affects product comprehension

The skill forces a decision gate: user decision, component family, material, states, tokens, files and scope.

## Claims Guardrail

RE-COMP has wellness, longevity and specialist-supported services.

Do not invent medical claims.

Use careful language:

- supports
- assesses
- informs
- helps guide
- personalizes
- tracks progress

Avoid unless approved:

- cures
- treats
- reverses disease
- prevents disease
- guarantees longevity
- eliminates inflammation
- diagnosis
