# App UI Pilot Assumptions

These assumptions must be validated against the original app and Claude redesign codebases.

## Product Assumptions

- ASSUMPTION: Health Score is a canonical top-level app metric.
- ASSUMPTION: Daily Overview is the most important consumer app surface.
- ASSUMPTION: Recovery, sleep and HRV are primary daily signals.
- ASSUMPTION: The app supports or will support AI guidance.
- ASSUMPTION: Human expert review exists or is planned.
- ASSUMPTION: Body Check is the baseline entry point.

## Data Assumptions

- ASSUMPTION: Wearable data may be available.
- ASSUMPTION: Biomarker data may be periodic, not daily.
- ASSUMPTION: Plan adherence is trackable.
- ASSUMPTION: Recommendations can use recovery and plan state.

## UX Assumptions

- ASSUMPTION: Users need one daily recommendation more than a dense dashboard.
- ASSUMPTION: Recovery Detail can be darker and more immersive.
- ASSUMPTION: AI Coach should be contextual and action-oriented.

## Unresolved

- UNRESOLVED: Exact user roles in implemented code.
- UNRESOLVED: Exact onboarding path.
- UNRESOLVED: Whether clinician and coach flows are in the current app.
- UNRESOLVED: Whether franchise/internal admin flows exist.
- UNRESOLVED: Actual Health Score formula or data model.
